The deep-roots roadmap

One program: go to the root layer of every field of computer science, from first principles, and stay there until the field’s insiders would nod. Modules are built in dependency order — each one is a root of the ones after it.

All seventeen modules are now LIVE — 107 chapters, ~360,000 words, per-chapter quizzes, labs, and seventeen final exams. The stack is complete from transistors to distributed systems.

Module 01 — memory models of programming languages · LIVE

The root of the roots. Every language answers four questions — what is a value, who owns it, who frees it, what safety is guaranteed — and every field downstream (security, compilation, mobile, databases, concurrency) is a consequence of those answers. Twenty-three chapters: silicon → hierarchy → virtual memory → stack → heap → object layout → assembly → sixteen languages → allocators → hardware memory model → memory security → mobile → unification. Start here.

Module 02 — memory security & exploitation · LIVE

The dark mirror of module 01: every memory-model decision is an attack surface. Stack smashing and canaries; heap metadata attacks (tcache poisoning, House-of-* lore); use-after-free as the modern bug class; ROP and code reuse; the mitigation ladder (ASLR/DEP/RELRO/CFI/PAC/MTE); Rowhammer and speculative cache side channels. 7 chapters + final exam. Start here.

Module 03 — software bugs: the taxonomy of failure · LIVE

The bug classes every senior engineer knows by scar tissue: memory corruption family, race family (data races, TOCTOU, deadlocks, priority inversion), numeric family (overflow, promotion traps, float money bugs, 2038), state family — and the machinery that finds them: fuzzing, sanitizers, bisect. 5 chapters + final exam. Start here.

Module 04 — decompilation & reverse engineering · LIVE

Reading what compilers leave behind. ELF/PE/Mach-O file formats from bytes up; the loader (PLT/GOT, RELRO, interposition); compiler idioms as fingerprints; vtable and RTTI reconstruction for C++; decompilers (Ghidra/IDA/Binary Ninja) — what they can and cannot recover; anti-analysis and the unpacking playbook. 6 chapters + final exam. Start here.

Module 05 — Android internals · LIVE

Zygote fork and the boot image; ART's object model and concurrent copying GC; Binder from the memory-map perspective (the 1MB buffer); lmkd and PSI-driven process kills; the per-app sandbox (UID, SELinux, seccomp); APK packaging, dex, signatures, and A/B OTA. 6 chapters + final exam. Start here.

Module 06 — iOS internals · LIVE

XNU memory management (16K pages, VM maps, zones), Jetsam bands and the compressor; Mach ports and message ownership; XPC and privilege separation; dyld launch closures and the shared cache (the biggest COW artifact you own); code signing as page-in validation; PAC. 5 chapters + final exam. Start here.

Module 07 — desktop OS internals (Windows / Linux / macOS) · LIVE

One architecture per pair: Windows (PE, TEB/PEB, LoaderLock, the NT heap and LFH), Linux (ELF, vDSO, slab, page cache, overcommit, the OOM killer's arithmetic), macOS (Mach VM, purgeable memory, unified memory) — the page-table knowledge of module 01 ch03 becomes three concrete implementations, compared in one final table. 6 chapters + final exam. Start here.

Module 08 — COBOL & the mainframe world · LIVE

The fixed-record universe deep dive: the z-machine (PSW, storage keys, addressing modes), WORKING-STORAGE/LOCAL-STORAGE/LINKAGE with exact semantics, PICTURE as a byte-level type system (COMP-3 layout arithmetic by hand), CICS transaction memory (GETMAIN, quasi-reentrancy, storage protection), and why the world's money still runs on a memory model with no heap. 5 chapters + final exam. Module 09 — concurrency & distributed memory · LIVE

From the hardware memory model to happens-before in distributed systems: the language memory orderings, the lock zoo (futexes, PI, lockdep), lock-free (CAS, ABA, hazard pointers, epochs, RCU), actors and channels as ownership transfer, and the distributed analog — Lamport/vector clocks, quorums, Raft, CRDTs, PACELC. 5 chapters + final exam. Start here.

Module 10 — compilers & language runtime internals · LIVE

Where the memory models of module 01 are manufactured: the pipeline and SSA, the optimizations that change memory behavior (SROA, alias analysis, UB-as-license), register allocation as the birthplace of the stack frame, escape analysis and write barriers and safepoints (the compiler's GC duties), and the ABI: mangling, calling conventions, vtable emission, layout decisions. 5 chapters + final exam. Module 12 — GPU & AI accelerator memory · LIVE

The tower's new wing: the GPU memory hierarchy (registers, shared memory banks, L2, HBM), coalescing as cache-line physics and the roofline model, allocation and the real anatomy of "CUDA out of memory" (the caching allocator, fragmentation), unified memory, Apple Silicon, and CXL — closing with the full register-to-RDMA tower table. 4 chapters + final exam. Module 13 — networking internals · LIVE

Module 14 — file systems & storage · LIVE

Start here.

Build order reasoning

Memory first because: security bugs are memory bugs (02, 03); decompilation reads stack frames and vtables (04); mobile OSes are memory-driven schedulers (05–07); COBOL is a memory model (08); distributed consistency is memory-model theory at scale (09); compilers manufacture memory models (10); databases are disk-scaled memory hierarchies (11); accelerators are a new hierarchy level (12). The second round went outward and downward: networking is buffers in motion (13); file systems are allocators that outlive the process (14); virtualization is the memory illusion sold as a product (15); the browser is the OS everyone actually runs (16); and hardware is the physics under every claim the program ever made (17). One root, seventeen trees.

What could come after

The program is extensible by design; the named frontiers now: cryptography internals (the math, the timing side channels, the implementation bugs), programming language theory & type systems (why Rust's borrow checker is a theorem), embedded & firmware (the world of no MMU), formal verification (the machines that prove kernels), and ML systems/training infrastructure (the distributed memory machine at datacenter scale). The method stays the same: first principles down, insider facts on the table, labs you can run, quizzes with teeth.
