The deep-roots roadmap

One program: go to the root layer of every field of computer science, from first principles, and stay there until the field’s insiders would nod. Modules are built in dependency order — each one is a root of the ones after it.

One program: go to the root layer of every field of computer science, from first principles, and stay there until the field's insiders would nod. Modules are built in dependency order — each one is a root of the ones after it.

All twenty-two modules are now LIVE — 132 chapters, ~476,000 words, per-chapter quizzes, labs, and twenty-two final exams — connected by 1,100+ explicit cross-module references (see the connections map on the site). The stack is complete from transistors to the datacenter, and the ring is closed: the theory that explains the languages, the proofs behind the promises, and the machines that train the models.

Module 01 — memory models of programming languages · LIVE

The root of the roots. Every language answers four questions — what is a value, who owns it, who frees it, what safety is guaranteed — and every field downstream (security, compilation, mobile, databases, concurrency) is a consequence of those answers. Twenty-three chapters: silicon → hierarchy → virtual memory → stack → heap → object layout → assembly → sixteen languages → allocators → hardware memory model → memory security → mobile → unification. Start here.

Module 02 — memory security & exploitation · LIVE

The dark mirror of module 01: every memory-model decision is an attack surface. Stack smashing and canaries; heap metadata attacks (tcache poisoning, House-of-* lore); use-after-free as the modern bug class; ROP and code reuse; the mitigation ladder (ASLR/DEP/RELRO/CFI/PAC/MTE); Rowhammer and speculative cache side channels. 7 chapters + final exam. Build order reasoning

Memory first because: security bugs are memory bugs (02, 03); decompilation reads stack frames and vtables (04); mobile OSes are memory-driven schedulers (05–07); COBOL is a memory model (08); distributed consistency is memory-model theory at scale (09); compilers manufacture memory models (10); databases are disk-scaled memory hierarchies (11); accelerators are a new hierarchy level (12). The second round went outward and downward: networking is buffers in motion (13); file systems are allocators that outlive the process (14); virtualization is the memory illusion sold as a product (15); the browser is the OS everyone actually runs (16); and hardware is the physics under every claim the program ever made (17). The third round closed the ring: cryptography is memory discipline where a cache miss is a breach (18); type systems are the theorems the languages run on (19); embedded is the whole stack with the safety net removed (20); verification is the machinery that proves what the other twenty-one modules only promise (21); and ML infrastructure is the memory model rebuilt at datacenter scale (22). One root, twenty-two trees.

What could come after

The program is extensible by design. The third round (modules 18-22) closed the named frontiers, and the current candidates for a fourth round: operating systems distributed beyond one machine (the cluster as the kernel), numerical & scientific computing (the memory model of floating point at scale), signal processing & media (the buffer discipline of real-time audio/video), and the economics of compute (the business layer that decides which of these machines gets built). The method stays the same: first principles down, insider facts on the table, labs you can run, quizzes with teeth, and every chapter connected to the roots.
