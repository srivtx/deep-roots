Twelve questions in five parts — three on the minimal machine (chapter 01), three on types as theorems (chapter 02), two on memory safety as a theorem (03), two on GC as proof search (04), two on the limits (05). Part I — the minimal machine (chapter 01)

  1. Predict. With TRUE = λa.λb.a, FALSE = λa.λb.b, define AND = λp.λq. p q FALSE and OR = λp.λq. p TRUE q, and let Ω = (λx.x x)(λx.x x). For each of AND FALSE Ω, AND TRUE Ω, OR TRUE Ω: does normal order terminate? Give the normal form with a short trace, then state in one sentence which argument position each operator is strict in. Finally: why must && in C be syntax rather than a function?
  1. Diagnose. A log scanner ships v1 and is refactored to v2 "for consistency"; after the change the service hangs on a live tail where v1 answered in milliseconds:
   hit = any(is_bad(l) for l in tail_log(sys.stdin))   # v1: returns fast
   lines = [l for l in tail_log(sys.stdin)]            # v2: hangs here
   hit = any(is_bad(l) for l in lines)

In evaluation-order terms: which redexes moved, from what position to what position? What is any's short-circuit in λ terms (name the chapter-01 shape)? What property of the argument does v2 wait for that Ω also never acquires?

  1. Derive. Strict languages cannot ship Y; they ship Z. (a) Unfold Y g one β-step, then show that evaluating the result under applicative order never applies g — trace two more steps and name the regrowing pattern. (b) Unfold Z g one step, where Z = λf.(λx.f (λv.x x v))(λx.f (λv.x x v)), and show that g now receives a value. (c) Which conversion is the λv wrapper an instance of, and why does call-by-value need it?

Part III — memory safety as a theorem (chapter 03)

  1. Derive. Suppose &mut T were covariant in T, so &mut &'long i32 coerced to &mut &'short i32 and back. Both programs below must end in a use-after-free with no unsafe block and no cast anywhere. (a) Shortening, write side — complete plant, then name the line that plants the dangling reference and the line that reads it:
   fn plant(r: &mut &'long i32, s: &'short i32) { /* coercion + store */ }
   fn main() {
       let long_lived = 42;                      // outlives everything below
       let mut slot: &'long i32 = &long_lived;   // slot's type promises 'long
       { let temp = 7;
         plant(&mut slot, &temp); }              // temp dies at this brace
       println!("{}", slot);                     // the read
   }

(b) Lengthening, read side — construct the symmetric program in which &mut &'short i32 coerced to &mut &'long i32 lets a short reference escape its region through the slot: fill in the coercion-and-read in escape and the body of the block, and mark the plant and read lines:

   fn escape(r: &mut &'short i32) -> &'long i32 { /* coercion + read */ }
   fn main() {
       let dangling: &'long i32 = {
           let temp = 7;
           /* declare slot; plant; call escape */
       };                                        // temp dies at this brace
       println!("{}", dangling);                 // the read
   }

(c) State the rule both programs force. (d) Why is the identical coercion on a shared & &'long i32 safe — and which chapter-02 runtime exception is that rule the compile-time version of?

Answers

Part I

  1. AND FALSE Ω → (λq. FALSE q FALSE) Ω → FALSE Ω FALSE → (λb.b) FALSE → FALSE — Ω was substituted into FALSE's argument slot and discarded without being entered. AND TRUE Ω → TRUE Ω FALSE → (λb.Ω) FALSE → Ω: diverges — TRUE returns its first argument, so the body uses q, and the substituted Ω becomes the result and reduces forever. OR TRUE Ω → TRUE TRUE Ω → (λb.TRUE) Ω → TRUE, Ω discarded at the last step. Strictness: AND is strict in its second argument exactly when the first is TRUE; OR exactly when the first is FALSE — short-circuiting is a property of the encoded operators, not special syntax. It only holds under normal order: strict languages evaluate every argument before the call fires, so an and(f, g) function would run g regardless — why &&, ?:, and if must be syntax in C-family languages (ch01).
  1. The refactor moved the is_bad(l) redexes from a substituted, demanded-lazily position to an evaluated-before-the-call position. v1: the generator hands any one element at a time; any stops at the first truthy value, so every later is_bad(l) redex is dead-branch material, never fired — question 1's AND FALSE Ω shape, with any's short-circuit as the IF consumer. v2: Python is applicative order — the argument [l for l in tail_log(...)] must reduce to a value before any is even entered, and an infinite tail never becomes one: exactly the property Ω never acquires. The fix is to pass the generator, not the materialized list — diagnose hangs by asking which redex moved (ch01).
  1. (a) Y g →β (λx. g (x x)) (λx. g (x x)) — call that argument A. A is a λ, hence a value, so the application fires: →β g (A A). Now applicative order demands the argument A A be a value before g runs; A A →β g (A A) — each evaluation of the argument regrows the same application: the argument is its own reduct, Ω-shaped; g is never called. (b) Z g →β (λx. g (λv.x x v)) B (B the second half), which fires to g (λv. B B v) — the argument is a λ, a value: g is applied immediately. When g's body invokes that thunk on a value v, B B v →β g (λv. B B v) v — one unfolding per recursive call, on demand. (c) η-expansion (λv. x x v ≡ x x, v ∉ FV(x x)): it delays self-application from "now" to "when the recursion is demanded" — exactly what call-by-value needs, why OCaml's and Scala's fix are Z, not Y (ch01).

Part II

  1. Case on the step rule: - E-IfTrue (t₁ = true, t' = t₂): D₂ is already a derivation of ⊢ t₂ : T — the conclusion, directly. No IH needed: the step selects an already-typed premise. - E-IfFalse: symmetric; D₃ supplies ⊢ t₃ : T. - E-If (congruence, t₁ → t₁'): IH on D₁ gives ⊢ t₁' : Bool; re-apply T-If with D₂, D₃ unchanged: ⊢ if t₁' then t₂ else t₃ : T — preserved. The same-type premise is load-bearing in the first two cases: the term has type T, the step yields t₂ (or t₃), and only the premise guarantees the selected branch has type T — drop it and E-IfTrue steps to an arbitrary-typed branch with nothing checked: preservation dead. The moral matches the application case: work rules select premises, congruence rules need the IH (ch02's Wright–Felleisen section).
  1. (a) Use f : S₁→S₂ where T₁→T₂ is expected. The context passes T₁ values; f must accept every one: T₁ <: S₁ — argument contravariant. f returns S₂; the context needs T₂ back: S₂ <: T₂ — result covariant. ∴ S₁→S₂ <: T₁→T₂ iff T₁ <: S₁ and T₂ <: S₂ — inputs flip, outputs don't. (b) Employee <: Person requires RichDate <: Date (depth subtyping). Through the Person view the field is writable: personView.birthday = plainDate typechecks — it is a Date field there. Through the Employee view, emp.birthday.richOnly() — a plain Date has no richOnly: the "well-typed" call detonates. A mutable field is an input and an output position at once — stored into and read from — so it must be invariant: the function rule applied to a field carrying both arrows. (c) IEnumerable<out T> exposes T only in output position — nothing consumes a T, so there is no store to lie through, and covariance is sound by the same derivation (ch02's variance section).
  1. (a) A parametric first receives only the list — elements are opaque α; it cannot inspect, compare, or construct an α. It can only return one of the elements (a position-shaped move) or diverge/throw — in a total world the type is uninhabited, which is why honest list-heads return Maybe α. null is a fabricated α — a value claiming membership in every type, Hoare's billion-dollar lie: the theorem ∀α. List<α> → α became provable with evidence that proves nothing. (b) Erasure compiled T to Object, so first returns an untagged reference and the call site's checkcast is the only proof — and null passes every cast (the universal inhabitant cannot be refuted). Reified arrays do catch wrong element types at the store (ArrayStoreException); erased generics cannot. (c) Optional<T> — the honest sum "value or absent" whose cases the caller must at least see; its cost is the discriminant: module 01 ch06's tagged-value layout returning as the certificate (ch02's null repair).

Part III

  1. (a) The completion is let shrunk: &mut &'short i32 = r; *shrunk = s; — covariance would coerce r down, and the store writes a &'short into a slot whose declared type still says &'long. Plant line: *shrunk = s. temp dies at the inner brace; read line: println!("{}", slot) — legal, because the slot's type promises 'long; it reads &temp: use-after-free, no cast anywhere. (b) The symmetric construction: fn escape(r: &mut &'short i32) -> &'long i32 { let widened: &mut &'long i32 = r; *widened } — the coercion at the binding, the extraction at *widened. Caller: inside the block, let mut slot: &'short i32 = &temp; (the plant — a short-lived reference enters a channel now typed long), then escape(&mut slot); the block's value binds outside as dangling: &'long i32, so it may outlive temp's brace; read line: the final println!. Shortening corrupts the slot for better-informed readers; lengthening exports the short reference past its region — both manufacture dangling pointers through the type's own promises. (c) &'a mut T is invariant in T: a mutable slot must accept exactly what its type says, in both directions, or every write becomes a runtime check. (d) A shared & &'long i32 cannot be written through — shortening it only forgets precision nobody can act on; readers holding the longer type still read the true, longer-lived value. That is chapter 02's covariant-arrays theorem hoisted to compile time: invariance is ArrayStoreException refused at the door (ch03's variance section).
  1. Clause by clause: (a) own-access — nobody: wild pointers survive to the MMU's 3-bit, 4 KiB-page check, C's row. (b) bounds — the runtime, at each access, in Debug/ReleaseSafe: slices carry lengths and the check fires on access — Go's row; in ReleaseFast, nobody — C's row again. (c) byte-level punning — nobody, but explicit: casts must be written (@bitCast), so the proof can only be suspended at greppable sites — an unsafe-shaped membrane without a compiler-held invariant list. (d) post-lifetime — nobody: manual frees make use-after-free first-class; defer gives scope-end determinism for frees you still must remember to write — RAII's intuition with no aliasing proof, C++'s row minus the refcount. Nearest rows: C — same (a), (c), (d), but Zig buys (b) the way Go does; and Go — same runtime bounds answer, but Go's GC closes clause (d) where Zig leaves it manual. ReleaseFast is not "a faster proof" — it is the proof rescheduled to never: check deleted, guarantee gone — ch04's Epsilon "no proof" row as a build mode; Debug vs ReleaseFast is one proof at two schedules (ch05's frame). CI ladder: suite in Debug (checks on), ASan for (b) and (d), MTE where present (15/16 caught), fuzz the C-interop membrane — that is the TCB (ch03).

Part IV

  1. (a) 12 GiB = 12,288 MiB; 12,288 / 400 MB/s ≈ 31 s stop-the-world. (b) 12,288 / 16 ≈ 768 MiB per marker → ~1.9 s, ideal. (c) 9.6× over the 200 ms SLO, and more threads buy little: each visit is a compulsory ~100 ns DRAM miss, so pointer-chasing marking is miss-ladder-capped — the memory bus, not the algorithm, limits the rate. (d) Generational — shrink the proof's subject: prove only the nursery, where 95-99% of objects are already dead and cost tracks survivors; concurrent — run the proof beside the mutator, paying a write barrier (CMS, G1, ZGC). (e) 8 MiB / 2 GiB/s = 4 ms, plus root and dirty-card scan: a young collection copies survivors; the other ~1,020 MiB is reclaimed as the side effect of emptying the nursery — cost ∝ survivor bytes, not allocation volume, which is why the 1 GiB appears nowhere. (f) 12 GiB / 512 B = 25,165,824 cards, one byte each = 24 MiB = 24 MiB / 12 GiB = 1/512 ≈ 0.2% of heap, always mapped; one stray old-to-young store dirties one card — a 512-byte re-scan at the next young GC (ch04).
  1. Concurrent mode failure: the concurrent mark-and-sweep could not finish before allocation filled the old generation — the proof could not keep pace with its subject's growth. The collector abandons the cycle and falls back to a full serial stop-the-world compacting collection on the already-huge heap — question 9(a)'s ~31 s at the worst moment, plus compaction. The structural cause: CMS never compacted old space — object identity is an address, compaction rewrites every pointer (forwarding pointers, Lisp-2's three passes), a cost CMS refused in the steady state; fragmentation accumulated until promotion could not fit in the holes — the O column pinned near 100 was the failure announced in advance. G1's redesign: ~2048 equal regions and a pause budget — -XX:MaxGCPauseMillis (default 200 ms), spent by a collection-set picker that predicts each region's evacuation cost and evacuates only what fits (young plus mixed old): a pause that is a slice of the proof sized to an SLO, at -5-15% throughput. The write barrier (Yuasa's snapshot: grey the overwritten value, ~2-20 ns/store) keeps the tri-color invariant — black never points to white — the proof correct; pace is not its job, and pace is what failed (ch04).

Part V

  1. (a) 90 s / 20 ns = 4.5 × 10⁹ executions. (b) Ten years nightly ≈ 3,650 runs: dynamic pays 3,650 × 20 ns ≈ 73 µs against 90 s once — dynamic wins by ~10⁶×. (c) 4,000 calls/s = 3.5 × 10⁸/day: break-even crossed in ~13 days; a year is 1.26 × 10¹¹ executions paying 2,520 s ≈ 42 min versus 90 s once — static wins ~28×, never billing mid-request. (d) The static bill already covered all paths — the 70% never executed cost the same 90 s, since static pays for all paths, including never-executed ones; dynamic pays nothing for them, but the 30% that do run pay forever. The unexecuted 70% are the error handlers you hope never fire: static is pre-payment for the disaster path, failing as a rejected build rather than a mid-request TypeError (ch05).
  1. (A) Rust proves soundness — never stuck — hence memory safety, not termination: fn f() -> ! { f() } typechecks (the never type advertises divergence); a wedged control loop violates no Rust theorem. The watchdog is the termination proof scheduled in hardware — "no progress by T, then reset" — the one check no type system can give you; the unsafe census remains the audit surface. (B) The total language makes termination a typing obligation — calls on structurally smaller arguments — so the loop cannot be written without lying; the lie is fuel (serve n bounds iterations: a watchdog moved into the type). The honest form is codata: the control loop as a coinductive process whose every observation delivers its next step in finite time — productivity: not "it stops," but "every step arrives." Both respond to impossibility 1 (termination); industry chose (A): over-accept, pay at runtime. Neither touches impossibility 3, the world — sensor reads and bus faults cross the process boundary no type cages — nor impossibility 2: "never command a burn that empties the tank" is a spec, not a type — filled by tests, module 21's machinery, or nothing (ch05; ch01's diagonalization, one last time).
